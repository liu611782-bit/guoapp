# 站源统一显示与「红果鉴」配置格式分析

## 当前事实

- 站源管理页只展示核心注册表（`sourceRegistryList`）中的条目；内置「红果」来自 `LocalStore.sources`，不在注册表里，所以管理页只看到导入源。
- 「全部站源」面板已同时列出内置源与已导入且启用的注册表源；注册表为空时自然只剩红果。
- 要让「管理页 ↔ 面板 ↔ 搜索/分类」完全实时一致，需要把内置源也抽象成统一 `SourceEntry`，并让导入/导出、开关、排序都走同一个本地注册表。

## 关于附件 `红果鉴外置站源一键配置-1028.json`

文件结构：

```json
{
  "format": "...",
  "version": 2,
  "sources": [ {"id":"hanxiaoquan","name":"韩小圈","entry":""}, ... 10 条 ],
  "connections": { "c_xxx": "https://huangguoai.com", "c_yyy": "BuildID=com.abc.Butterfly;SysType=ios;..." }
}
```

要点：

1. 它是「红果鉴」这个特定适配器的配置，不是通用 MacCMS / JSON 站源列表；`sources` 只有 id/name/描述，`entry` 为空，没有可直接请求的 API 地址。
2. `connections` 里混有域名、目录片段、以及伪造设备头（`BuildID=...;SysType=ios;DevID=...;DeviceModel=iPhone` 等）。这类内容依赖私有接口与设备伪装，本应用不实现伪造设备/绕过访问控制，也不会内置该适配器。
3. 若把它硬导入注册表，只会生成 10 条没有可用 URL 的条目，仍然打不开内容。

## 因此

- 要使用该配置，需要原作者 App 的适配器逻辑；本工程无法直接消费。
- 通用可导入的格式仍是：JSON 数组 / `{sources:[...]}` / `{sites:[...]}` / TXT 每行 URL / base64 订阅 / MacCMS API。
- 下一步改造方向：统一本地注册表（内置源 + 导入源同一份数据），导入导出、开关、排序、分类、面板全部读同一数据源；这需要重写站源管理页与 App 启动时的注册表合并逻辑，不是单点修补。
